# 职业与武将重分配建议

> 目标：把当前表中的职业（Job）与武将（Hero）对应关系整理到满足以下规则：
>
> - 每个职业最多 6 人；
> - 同职业的武将尽量品质（Quality）分散，不要都为同一品质；
> - 每个势力（Side）内，同职业最多 2 人；小势力（暂定义为 Side 值较少的势力，或自定义名单）内，同职业最多 1 人；
> - 对于职业人数过多的情况，优先把低优先级/低品质/重复定位的武将迁移到与其定位相近的职业；
> - 保持可回溯：所有迁移在表中保留注释并在版本控制里单次提交明确说明理由。

---

## 一、当前问题与衡量口径

说明：目前武将配置位于 `Assets/Resources/Scripts/Configs/HeroConfig_s.cs` 的 `Load()` 方法里（代码内 `config[xxxxx] = new HeroConfig(...)`）。

建议的衡量字段：

- Job（职业字符串）
- Quality（品质：1 普通，2 优秀，3 精良，4 史诗）
- Side（阵营/势力数字）
- Id / Name（用于明确修改目标）

备注：在开始大规模改动前，优先通过脚本导出当前 Job->Hero 列表并统计每个职业的人数与按 Side 分布（下面给出脚本示例）。

## 二、自动化检查与重分配脚本（建议）

步骤：

1. 从 `HeroConfig_s.cs` 的 `Load()` 里解析所有 `config[...] = new HeroConfig(...)` 行，抽取 Id/Name/Job/Side/Quality。
2. 统计：
   - 每个 Job 的总人数；
   - 每个 (Job, Side) 的人数；
   - 每个 Job 的品质分布；
3. 找出违反规则的项：Job 总数 > 6，或 (Job, Side) 人数 > 2（或小势力>1）。
4. 对每个违反项，生成候选迁移表：
   - 候选优先级：低品质（Quality 小）> 在职业中定位重复（例如纯防守/纯输出过多同质）> 技能/定位容易迁移的英雄；
   - 目标职业选择：与源职业定位相近的职业（示例映射见下节“建议迁移目标”）；
   - 选目标职业时同时满足：目标职业迁入后人数 <= 6，且 (目标Job, 该Hero.Side) 不超过上限。
5. 输出一个“迁移计划草案”文件，列出每一行：HeroId / Name / 原Job -> 目标Job / 原因 / 预计影响。
6. 人工复核后按批次应用到 `HeroConfig_s.cs`（在调用 Add/Assign 或直接修改 Load() 中的 Job 字段），并在 commit message 中记录变更内容与理由。

示例（伪 Python）脚本核心思想：

- 遍历文件，正则提取 new HeroConfig(...) 的参数列表；
- 参数解析后入数据结构，执行上述统计与规则校验；
- 生成 CSV/Markdown 的迁移建议表供策划/策划复核。

## 三、建议迁移目标（定位相近的职业对照）

当需要把某武将从 A 职业移动到 B 职业时，优先选择与 A 定位接近的 B：

- 刺客/后排偷袭类：马（刺客向）
- 近战领主 / 万金油坦克：帅 / 车
- 近战控制 / 晕眩：枪
- 重装 / AOE 溅射：戟
- 远程物理（攻速向）：弩（迅捷射手）
- 远程物理（攻击向）：弓 / 炮（区分为单体高伤 vs AOE）
- 法术控制 / 范围伤害：谋 / 棋
- 辅助/治疗：琴 / 医 / 相（士兵增益类）
- 光环/祝福类：鼓 / 琴

说明：具体职业间可根据技能语义微调（例如把具有“控制/减速/眩晕”效果的弩型武将转给谋或棋）。

## 四、迁移优先策略（实际操作顺序）

1. 统计并列出超载职业（人数>6），按人数超载量降序。
2. 对于每个超载职业，列出该职业所有武将，按品质升序（Quality 小优先）与是否在小势力（小势力优先迁出）排序。
3. 依次尝试把每个候选武将迁移到首选目标职业（参考上节），确保目标职业的约束满足；若不满足，再尝试下一个目标职业。
4. 若某武将确实无法迁移（因规则冲突），标记为“需人工裁定”，并列出替代方案（例如把其他职业中的可迁移武将迁入、或降级到低频上阵池）。

### 5.3 语义亮点（技能与职业羁绊的化学反应）

- **连→弩**：徐晃/甘宁/周泰的"连击"与弩(迅捷射手攻速流)天然契合，实际迁了徐晃（S2 弓超限）+ 锤收周泰。
- **羽→弩**：马岱/马腾/吕布/赵云/吕蒙的"能够射出箭矢"直接证明其远程能力，迁马岱/马腾至弩零违和。
- **火→炮**：徐庶/许攸/程昱/李儒的"攻击时放火"与炮车(火攻AOE)完美对应。
- **负面系→扇**：贾诩(扩散)/法正(溃败)正是扇"负面持续+10%~30%"的倍率放大器。
- **智力增益→琴**：陈宫(励)/庞统(锁)强化单核，呼应琴"集中培养"思路。
- **容量调配**：貂蝉(无技能)由琴调至医——S4 为小势力（9 人各职业限 1），琴 S4 之位留给语义更配的陈宫，医 S4 空位承接。
- **伏→弩**：李典/朱桓"瞬移到远程攻击者附近"是反远程特化，配弩/远程体系。

## 九、分析结论：如何调整 Hero 的 Job（2026-09-02 第三版：最终方案定稿）

### 9.1 选人与去向方法论

1. **候选池**：仅超载职业（棋19/枪11/弓9/戟9/相9/车9/马8）中，(Job,Side) 超上限（▼）或同品质>2（◆）的武将——
   见第一附表 Hero 列表标注。势力核心（诸葛亮/郭嘉/关羽/吕布/赵云等）一律保留。
2. **去向判定**：以 Skill1/Skill2 效果实测语义为准（见 5.1 技能依据列），
   输出/控制系→炮/扇，增益/辅助系→琴/医/鼓，箭矢/连击/反远程系→弩，近战爆发/反击系→锤。
3. **硬校验**：迁移后逐职业复核 (Job,Side) ≤2（小势力 ≤1），全员通过（见 5.2）。

### 9.2 容量缺口的处理

103 人 > 16 可用职业 × 6 = 96，缺口 7 人无法回避。本方案让棋/车/枪/弓/戟/鼓/锤 7 个职业各 7 人消化缺口，
而非集中某一职业（避免 13 人巨型职业）；后续若实装盾（容量+6）可回落到全职业 ≤6。

### 9.3 迁移聚焦的问题修复

- **棋×S1=5（蜀谋士团）**：留诸葛亮，徐庶/庞统/马谡/法正 4 人全迁（炮/琴/医/扇 各得其所）。
- **棋×S2=4（魏谋士团）**：留郭嘉/司马懿，荀攸/程昱迁医。
- **枪×S2=4（魏枪兵）**：留曹仁/庞德，曹洪/李典迁出（锤/弩）。
- **医×S10=2 / 马×S10=2 / 车×S4、S6=2 / 棋×S4、S6=3**：小势力超限全部清零。
- **空置职业拉活**：弩1→6、锤1→7、鼓2→7、琴3→6、医2→6。

### 9.4 品质结构评估（迁移后）

- 锤（q3×2/q2×2/q1×3）、弩（q3×2/q2×4）、鼓（q3×1/q2×3/q1×2）形成"普通~精良"梯度，符合成长型职业定位。
- 棋（q4×4）、车（q4×6）保留顶级浓度——法系/冲锋核心位，符合"高品质核心"原则。
- 迁出者以 q1/q2 为主（蒋琬、司马师、乐进、潘璋等 8 名 q1~q2），对原职业强度无损。

用户要求：Q1 尽量一职一个。16 个 Q1 原分布：扇3/炮3/锤3/士2/鼓1?（详见一·附表 ◆q1 标注），棋/车/弓/马/弩/琴/帅/相? 无 Q1。
