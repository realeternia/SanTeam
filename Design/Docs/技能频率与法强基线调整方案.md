> 前置分析：[满星物理法术伤害占比分析](满星物理法术伤害占比分析.md)（结论：满星全池 物理 77.8% / 法术 22.2%，明显偏物理）
> 状态：备选杠杆 C（伤害/治疗系数拆分 + 伤害 ×1.5、治疗回调 15%）已实施；A/B 主线待评审。

## 一、目标

| 指标 | 现状 | 目标 |
|---|---|---|
| 满星全池法术占比 | 22.2% | **38% ± 3%**（中档方案） |
| 法核单卡法术占比 | 61%~74% | 80%~88% |
| 物理主C 单卡技能占比 | 5%~37% | 30%~50% |
| 主C 技能释放间隔 | 9~20 秒 | **6~10 秒** |
| 平均法强 ap（法系） | 0 | 40（5星约 70，+70%） |

约束：
- 不改变「星级只同步放大」的结构（atk ×1.55/星、技能 Lv 曲线 ≈6×）。
- 尽量只动配置（JobConfig / CombatConst / 少量 HeroConfig），战斗逻辑只允许一处改动（ap 星级成长曲线）。

## 二、方案总览

两条主线，可独立上线、分批观测：

- **A. 技能频率**：只提高「回蓝」，**不下调 MP 成本**。
- **B. 法强基线**：职业 Ap 基线 + 英雄 Ap 修正 + ap 独立星级成长 + 装备/Buff 补强。

### ⚠ 关键陷阱：降 MP 成本不会提升技能 DPS

技能单发强度烘焙时经过 `mpFactor = clamp(MpCost/100, 0.2, 2)`（[CombatConst.SkillMpStandard](../../Assets/Resources/Scripts/Combat/CombatConst.cs)、[ConfigManager.PostModify](../../Assets/Resources/Scripts/Configs/ConfigManager.cs)）：

```
技能DPS ≈ 强度 × (MpCost/100) / (MpCost / 回蓝速度)  →  MpCost 被约掉
```

即「MP 70→45」会让释放频率 ×1.56、单发强度 ×0.64，**持续 DPS 基本不变**（只是更平滑）。若确实要降 MpCost，必须把 `SkillMpStandard` 同步从 100 提到 130~150，否则改了个寂寞。
本方案 A 主线因此只动**回蓝**，不动 MpCost，避免重生成 `SkillBaseConfig` 全表。

## 三、A 主线：技能频率

### A1. 职业回蓝基线（[JobConfig_s.cs](../../Assets/Resources/Scripts/Configs/JobConfig_s.cs)，构造参数第 12 个 = MpRegen）

| 职业分组 | 职业 | 现值 | 调整为 |
|---|---|---|---|
| 法系 | 扇 / 相 / 棋 / 鼓 / 琴 / 医 | 0 | **45** |
| 法系炮台 | 炮 / 工 | 0 | **30** |
| 其他 | 王 / 马 / 车 / 弓 / 弩 / 士 / 盾 / 锤 / 枪 / 戟 | 0 | **15** |

- 语义：百分比加成，`英雄 MpRegen = 职业基准 + 英雄修正`（加法，[ConfigManager](../../Assets/Resources/Scripts/Configs/ConfigManager.cs) 第 96 行），只在普攻/受击回蓝时作为倍率。
- 效果：法系回蓝 6.7 → 9.7 MP/s，70 MP 技能 10.5s → 7.2s。

### A2. 全局普攻回蓝（[CombatConst.cs](../../Assets/Resources/Scripts/Combat/CombatConst.cs) `MpPerAttack`）

| 常量 | 现值 | 调整为 |
|---|---|---|
| `MpPerAttack` | 10 | **12** |

- 与 A1 叠加后：法系 = 12×1.45 ≈ 17.4 系数（相对现值 10 → ×1.74），70 MP 技能约 **6.0s** 一发，110 MP 约 9.4s。
- 注意：该常量对士兵同样生效，士兵技能会一起变快（见风险 4）。

### A3. 开局法力（可选，逐技能配）

- 给 3~5 个「开场爆发」类技能把 `StartMpRate` 配成 0.2~0.3（[SkillConfig_s.cs](../../Assets/Resources/Scripts/Configs/SkillConfig_s.cs) 第 15 列），只影响首轮，不改变持续 DPS。
- 默认 0 不动，避免全英雄开场集体放技能。

### A4. 不做的事

- 不下调模板 `MpCost`（[SkillTemplateConfig_s.cs](../../Assets/Resources/Scripts/Configs/SkillTemplateConfig_s.cs) 第 12 个参数）与组件「MP中增加 / MP大增加」（[SkillTemplateComponentConfig_s.cs](../../Assets/Resources/Scripts/Configs/SkillTemplateComponentConfig_s.cs) 120~125 行），原因见第二节陷阱。
- 若后续仍要降，需把 `SkillMpStandard` 100 → 130~150，并重生成 `SkillBaseConfig`。

## 四、B 主线：法强基线

### B1. 职业法强基线（[JobConfig_s.cs](../../Assets/Resources/Scripts/Configs/JobConfig_s.cs)，构造参数第 6 个 = Ap）

| 职业分组 | 现值 | 调整为 | 满星(×1.15⁴) |
|---|---|---|---|
| 法系 扇/相/棋/鼓/琴/医 | 0 | **40** | ≈ 70（+70% 技能伤害/治疗/护盾） |
| 炮 / 工 | 0 | **18** | ≈ 31 |
| 其他职业 | 0 | **8** | ≈ 14 |

- 语义：`(100+ap)/100` 为法术技能倍率（[Skill.GetSkillDamage](../../Assets/Resources/Scripts/Combat/Skill/Skill.cs)），ap=40 即 +40%。
- **注意 ap 同时作用于治疗与护盾**（HealStrength / shield 走同一口径），见风险 1。

### B2. 英雄法强修正（[HeroConfig_s.cs](../../Assets/Resources/Scripts/Configs/HeroConfig_s.cs)，第 9 列 = Ap）

- 语义：相对职业基准的百分比修正，`英雄 ap = 职业 ap ×(100+本列)/100`（[ConfigManager](../../Assets/Resources/Scripts/Configs/ConfigManager.cs) 第 97 行）。
- 只给法核加，示例（数值待评审）：

| 英雄 | 职业 | 建议修正 | 说明 |
|---|---|---|---|
| 李儒 | 扇 | +60 | 持续/群体法核 |
| 诸葛恪 | 扇 | +40 | 群体法核 |
| 庞统 / 钟会 | 棋 | +40 | AOE 法核 |
| 王基 | 炮 | +30 | 法系炮台（攻击也高，避免过高） |
| 张角 | 工 | +30 | 法术输出 |
| 其他物理主C | — | 0 | 不额外加成 |

### B3. ap 独立星级成长（唯一代码改动）

现状 [HeroSelectionTool.GetHeroAttr](../../Assets/Resources/Scripts/Tools/HeroSelectionTool.cs) 第 377 行对 Ap 也用 `StarGrowthPerStar=1.55`。**若保持现状又给职业 ap=40，5星 ap 会变成 40×5.77 = 231（+231% 技能伤害），数值会直接失控**。

改法：

- 在 [CombatConst.cs](../../Assets/Resources/Scripts/Combat/CombatConst.cs) 新增常量：
  ```csharp
  /// <summary>法强(Ap)专属星级成长系数（与攻击/生命的1.55区分，避免5星ap过热）</summary>
  public const float ApGrowthPerStar = 1.15f;
  ```
- `GetHeroAttr` 中 Ap 改走独立曲线：`Ap = Round(Ap × ApGrowthPerStar^(lv-1))`，Atk/Hp 不变。
- 品质系数仍**不作用于 Ap**（保持现有口径，注释见 ConfigManager 第 100 行）。

### B4. 装备 / Buff 法强补强（第二批，可选）

- [ItemConfig_s.cs](../../Assets/Resources/Scripts/Configs/ItemConfig_s.cs)：羽扇 10→15、长信宫灯 25→35、孙子兵法 15→20（具体按现表微调）。
- 曹操「护驾」ap+30 → +45（[SkillConfig_s.cs](../../Assets/Resources/Scripts/Configs/SkillConfig_s.cs)）。
- 目的：让「堆法强」成为可行流派；同时同步检查治疗/护盾收益。

### 备选杠杆 C：品质技能系数整体 ×1.5（已实施：伤害/治疗拆分）

改法（已落地）：把原 `QualitySkillFactors` 拆成两个系数表（[CombatConst.cs](../../Assets/Resources/Scripts/Combat/CombatConst.cs#L156-L160)）：

| 系数表 | Q1 | Q2 | Q3 | Q4 | 说明 |
|---|---|---|---|---|---|
| `QualitySkillDamageFactors` | 1.5 | 2.4 | 3.3 | 4.5 | 作用于 DamageStrength，原表整体 ×1.5 |
| `QualitySkillHealFactors` | 1.275 | 2.04 | 2.805 | 3.825 | 作用于 HealStrength，伤害系数回调 15%（×0.85） |

- 作用范围：仅英雄专属技能的 `DamageStrength` / `HealStrength`（[HeroScenario](../../Assets/Resources/Scripts/Tools/HeroScenario.cs) 第 194~200 行烘焙）；兵种/道具技能、`Strength2`（护盾、溅射、DOT 系数）**不受影响**。
- 品质间比值不变（Q2/Q1 仍为 1.6），所以它**不会拉开品质差距**，只是全量平推。

| 场景 | 全池法术占比 | 普攻 | 技能物 | 总 DPS |
|---|---|---|---|---|
| 现状（5星） | 22.2% | 74.7% | 3.1% | 40304 |
| **仅 ×1.5** | **29.9%** | 67.2% | 2.9% | 44804（+11%） |
| ×1.5 + 低档回蓝/法强 | 40.6% | 56.9% | 2.5% | 52895（+31%） |
| ×1.5 + 中档回蓝/法强 | 47.5% | 50.2% | 2.3% | 59970（+49%） |

1星同口径：22.4% → 30.2%（各等级行都乘，低星节奏一起变快）。

代表单卡（5星，仅 ×1.5）：李儒 74%→81%、王基 62%→71%、典韦 55%→65%、孙策 37%→47%、马超 23%→31%、吕布 16%→22%。

代价与风险：

1. **治疗同步提升 +27.5%**：13 个英雄技能的 HealStrength 合计 5585 → 约 +1536（治疗系数已从 ×1.5 回调 15%，若维持 ×1.5 则为 +50%，奶队会明显超标）；护盾（Strength2）不变。
2. **攻击驱动/机制型技能不获益**：张飞（DS=0，靠 splashRate）、所有 Strength2 机制原地不动 → 相对贬值约 33%，物理系体感变弱。
3. **频率没变**：仍是 9~20 秒一发，只是单发更痛——与金铲铲的主要差距是频率与 AP 杠杆，不是单发数值。
4. 总 DPS +11%（单上）→ 对局时长约 -8%；若与中档方案叠加到 47.5% 则节奏过快、数值膨胀 +49%。

**建议**：若要低风险过渡，用「×1.5 + 低档回蓝/法强」（40.6%）一次到位；不要「×1.5 + 中档」（47.5% 已冲过对标区间）。
