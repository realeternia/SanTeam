# 金币商店双模式抽象（共享轮换 + 金铲铲式独立买卡）

## 一、目标（Summary）

为卡片商店引入一层**明显的模式抽象**，支持两种商店流程，并按回合配置切换，方便后续扩展（如引入共享有限卡池）：

1. **共享轮换模式（现有逻辑，ShopType=0）**：8 名玩家共用 15 格商店，按积分低→高轮流买卡，可“跳过”，卡牌有售出倒计时/相邻刷新。
2. **独立买卡模式（金铲铲式，ShopType=1）**：每个玩家拥有**自己的 5 格私有商店**，人类只能看/买自己的，AI 商店隐藏；人类可自由买卡、花 2 金刷新自己 5 格，点“结束”后各 AI 依次计算并购买自己的商店，然后进入战斗。
3. **AI 同时适配两种方案**：AI 买卡逻辑与“商店展示对象”解耦，改为接收一份 `ShopOffer` 报价列表，两种模式共用同一套评分/购买代码，并可自行刷新。

切换开关：`GameRoundConfig` 新增 `ShopType` 列（0=共享轮换，1=独立买卡）。

#### （1）`Assets/Resources/Scripts/Shop/ShopMode.cs` — 抽象层

包含 `ShopModeType` 枚举、`ShopOffer` 报价结构、`ShopMode` 抽象基类。

```csharp
// 商店模式类型（与 GameRoundConfig.ShopType 取值一致）
public enum ShopModeType { Shared = 0, Independent = 1 }

// 一份“可购卡报价”：把人类可见卡位与 AI 隐藏商店统一成一个数据结构，
// 让 AI 评分逻辑不再直接依赖 CardViewControl。
public class ShopOffer
{
    public int cardId;
    public bool isHero;
    public int price;   // 单价
    public int count;   // 剩余可购数量
    public CardViewControl view; // 可见卡位（人类/共享牌）；AI 隐藏商店为 null
}

// 商店流程抽象基类：CardShopManager 作为“宿主”提供预制体/容器/布局/购买/收尾，
// 具体模式只负责“生成本商店 + 操作节奏 + 回合推进”。
public abstract class ShopMode
{
    protected CardShopManager host;
    public void Bind(CardShopManager h) { host = h; }
    public abstract ShopModeType Type { get; }

    // 商店阶段开始（宿主已完成 BGM/加钱/排序/year++/era 公共开场）
    public abstract void Begin();

    // 当前“操作中”玩家：共享=回合玩家；独立=人类(pid0)
    public abstract PlayerInfo GetActingPlayer();

    // 某玩家当前可购卡（共享=全部未售共享卡；独立人类=可见卡位；独立AI=私有商店数据）
    public abstract List<ShopOffer> GetOffers(int pid);

    // 任一玩家买卡成功后（共享：触发售出倒计时/相邻刷新；独立：无）
    public virtual void OnBought(ShopOffer offer, PlayerInfo player) { }
    // 仅“人类”买卡成功后（共享：推进回合；独立：无）
    public virtual void OnHumanBought(PlayerInfo player, ShopOffer offer, int buyCount) { }

    public abstract void OnHumanPass();     // 点击“跳过/结束”
    public abstract void OnHumanRefresh();  // 点击“刷新”
    public abstract IEnumerator Drive();    // 推进协程（AI 行动/等待人类），结束时 host.RequestEnd()

    public virtual void End() { }
    protected static bool IsPanelBlocked() { /* 供两种模式复用：商店以外的面板打开时暂停 AI */ }
}
```

#### （3）`Assets/Resources/Scripts/Shop/IndependentShopMode.cs` — 独立买卡实现

- 私有状态：`humanEnded`、`Dictionary<int, List<ShopOffer>> aiShops`、每回合 AI 刷新次数上限（读 `CombatConst`）。
- `Begin()`：
  - `host.ClearCards()`；为人类(pid0)生成 **5 格**私有商店（同 `GetRandomShopHeroId` + `host.GetMultiCount` 规则）→ `host.cardViews` + `host.LayoutCards(host.cardViews, 5)`；同时对 pid 1~7 各生成 5 条 `ShopOffer`（无 view）缓存进 `aiShops`。
  - `host.passBtn` 显示且文案设“结束”；`host.refreshBtn` 保持可用；`humanEnded=false`。
  - `GameManager.OnPlayerTurn(0)`；`host.mySelect.UpdateCards(human)`。
- `GetActingPlayer()` → 人类(pid0)；`GetOffers(0)` → 由 `host.cardViews`（未售）实时映射；`GetOffers(pid>0)` → `aiShops[pid]`（可变对象，购买后回写 `count`）。
- `OnHumanPass()` → 仅人类可点，置 `humanEnded=true`。
- `OnHumanRefresh()` → 校验 2 金 → `RefreshShopFor(0)`（人类 5 格全部重掷）。
- `RefreshShopFor(pid)`：扣 2 金；pid==0 时对 `host.cardViews` 5 格逐一 `host.ReplaceCardAt(i, newHeroId, newCount)`；pid>0 时重建 `aiShops[pid]` 5 条。
- `Drive()`：
  ```
  等待 humanEnded（期间可买/刷新；面板阻塞时暂停推进）
  for pid in 1..7:
      offers = GetOffers(pid); guard=0; refreshes=0
      while (guard++ < 20)
          if (AiCheckBuyCard(player, host.Era, offers)) continue
          if (refreshes < AiMaxShopRefreshPerShop && player.gold >= RefreshGoldCost*2) { RefreshShopFor(pid); refreshes++; continue; }
          break
      等待 SysRandom.Range(0.25~0.5)s（节奏）
  等待 0.4s → host.RequestEnd()
  ```

## 四、假设与决策（Assumptions & Decisions）

1. **模式切换规则**：按用户答复“非怪物回合都改成独立买卡”理解为 → **怪物回合（`RoundType==1`）保留原共享商店，非怪物回合（`RoundType==0`）改为独立买卡**。若与预期相反，只需翻转 `ShopType` 列数据（结构不变）。
2. 人类只显示/操作 **自己的 5 格**（独立模式），AI 商店**不实例化任何 UI**，仅用 `ShopOffer` 数据对象，避免每回合 40 个隐藏卡位。
3. **暂不引入共享有限卡池**（卡池无限），但 `ShopOffer` / `ShopMode` 抽象已为“消耗/争夺卡池”预留扩展点（未来在 `GetOffers`/购买成功后扣减池）。
4. 独立模式人类点“结束”后，AI 依次计算并购买（含可自行刷新），完成后进入战斗。
5. 独立模式“刷新”= 花 2 金重掷**自己全部 5 格**；AI 同样可刷（受 `AiMaxShopRefreshPerShop` 限制、且保留 ≥2 金可再刷）。
6. `jadePlayer`/`firstJumper`/`playerStartGold` 保留在 `CardShopManager` 作为宿主 public 字段（避免改动 `ShopPanelBg.prefab` 的序列化字段）；仅共享模式使用 `jadePlayer/firstJumper`。
7. 共享模式行为**零回归**：轮换、pass、售出倒计时、相邻刷新、AI 依次买卡、2 金刷新 6 张等均保持原样，仅做代码搬迁。
8. `CheckEraBonusGold`（落后补金）作为宿主公共逻辑，两种模式都会执行。
9. 批处理模拟器（`Tools/战斗模拟器/`）不涉及商店，无需改动。
