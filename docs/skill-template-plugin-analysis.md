# Q1–Q2 英雄技能模板与插件拆分分析（初稿）

> **文档目的**：在不改战斗逻辑的前提下，梳理品质 1–2 英雄技能的模板项和插件项，为后续建立技能预算、降低技能配置压力做准备。
>
> **状态**：设计分析初稿；本文不修改战斗逻辑、不调整现有技能配置，也不把尚未用实战数据校准的点数标价当成最终平衡结果。

## 1. 分析范围与品质口径

本分析的主体是武将个人技能：`HeroConfig.Skill1` 指向的英雄专属技能配置（`SkillConfig.Sname` 与英雄名对应）。职业技能、好友连线技能、道具技能不属于本次个人技能样本；若后续要统一设计系统，可另立章节纳入。

英雄品质不是一个全局固定值，而是分别写在 `HeroConfig.Scenario1/Scenario2/Scenario3` 中，格式为“品质:阵营”，例如 `2:蜀`。因此：

- 以“某个指定剧本”分析时，只选该剧本中品质为 Q1 或 Q2、且实际出场的英雄。
- 以“全项目低品质技能池”分析时，纳入**至少一个剧本**品质为 Q1 或 Q2 的英雄个人技能，并标出对应剧本与品质；同一技能只列一次，不能因为跨剧本重复而重复计数。
- 不应仅凭某一剧本或单个英雄品质判断该技能始终是低品质技能。
- 英雄品质技能修正需与模板预算分开记录。当前项目对英雄专属技能的伤害/治疗基值使用品质系数；因此预算对照建议先还原到 Q1 基准，避免重复计入品质倍率。Buff 等其他效果不应未经验证就沿用相同倍率。

## 2. 模板项与插件项的定义

### 2.1 模板项：决定技能的基础形态

模板描述“技能如何选取目标和结算”，应尽量少而稳定。第一轮建议包括：

| 模板 | 基本语义 | 常见配置字段/行为 |
| --- | --- | --- |
| 单体伤害 | 对一个敌方目标结算一次伤害 | `Range`、`DamageType`、`DamageStrength` |
| 单体控制/伤害 | 对一个敌方目标造成伤害或控制，可附带伤害 | `Range`、`BuffId`、`BuffTime` |
| 圆形范围伤害 | 以目标点或施法者为中心，对圆形范围选人 | `Range`、`Area`、中心语义、`TargetCount` |
| 单体治疗/增益 | 选择一个友方单位进行治疗或施加增益 | `Range`、目标筛选、治疗/增益字段 |
| 范围治疗/增益 | 对范围内友方单位施加效果 | `Area`、目标数、目标筛选 |
| 持续区域 | 创建持续一段时间的区域，周期结算伤害/控制 | `Area`、`SummonTime`、`SummonHitInterval` |
| 自身强化 | 对施法者施加短时或永久效果 | `BuffId`、`BuffTime`、`Strength2`/`StrengthBuff1` |
| 光环/全局效果 | 对我方单位持续或全局施加属性效果 | `AuroAttrs`、光环专属数值 |

**模板不能只按分类标签判断。** 同为“群伤”，目标中心圆形、自身中心圆形、直线穿透、弹道逐个命中、持续区域的命中机会和结算次数不同。若目标选择/结算方式明显不同，应定义成不同模板或单独机制模板，而不是当成廉价插件。

### 2.2 插件项：可独立选择、估价的效果或限制

| 插件类别 | 典型项目 | 估价要点 |
| --- | --- | --- |
| 伤害/治疗数值 | 伤害档位、伤害倍率、治疗量 | 先明确是固定基值还是属性成长；伤害和治疗分别标定 |
| 射程 | 增加施法距离 `Range` | **作为插件**；与攻击射程、AoE 半径区分，按可触达目标和触发成功率估值 |
| 目标数 | 最多命中 N 个目标、单目标/多目标上限 | **作为插件**；有限目标数与范围内全部目标分开；配置中的 `TargetCount <= 0` 在不同脚本中可能表示不限，不可按零成本处理 |
| AoE 范围档 | 小范围、中范围 | 可做模板档位，也可在同一模板中按范围等级计价；应考虑实际预期命中数，而非只按半径线性估价 |
| 状态效果 | 减速、减防、减攻、减疗、增伤、眩晕、定身等 | 按效果类型、强度、持续时间、命中对象数综合估值 |
| 多段/持续 | 连击、DOT、周期伤害、持续施法、持续区域 | 按预期总段数/持续结算次数估价，避免只按单次伤害估值 |
| 目标筛选 | 最低血量、后排、英雄限定、友军类型等 | 选择性越强未必单纯越贵；需看筛选是否提高击杀、救援或覆盖效果 |
| 特殊机制 | 斩杀、驱散、破盾、位移、召唤、永久成长、复制等 | 初期列为特殊项，人工评审，不建议直接套用普通伤害价格表 |
| 施放节奏 | MP、CD、发动概率、触发条件 | 作为预算修正项或独立插件；要用实际发动频率校准，不能和单次效果成本混为一项 |

### 2.3 射程与范围必须分别记录

- `Range`：施法/选取距离，决定目标是否可被技能触达。
- `Area`：范围半径或部分技能的空间范围，决定选人覆盖区域。
- `TargetCount`：命中人数上限，不等于 AoE 半径。

例如“射程提高”应计射程插件；“小范围改中范围”计范围档；“最多命中 2 个改最多 4 个”计目标数插件。三者独立记录，避免把同一个范围收益重复算价。

## 3. Q1–Q2 技能池的初步形态分类

以下是用于建立审查表的**形态分类和代表性技能**，不是已完成逐个技能逐级校验的最终名单。全量名单应依第 1 节的剧本过滤规则从配置自动导出，再逐项核对技能行和实际脚本行为。

| 初步形态组 | 可作为样本核对的个人技能 | 识别到的插件方向 |
| --- | --- | --- |
| 单体伤害/附带减益 | 腾驾、先锋斩、归汉、猎鹰、标记、断粮、毒箭、江河、律令、崩山、偷刃 | 减甲/减攻/减疗、DOT、法力燃烧、破甲、射程 |
| 单体伤害/附带控制或特殊条件 | 乱政（刘表）、舌辩、守势、御斩、隐忍、偷渡阴平 | 减速、定身、叛逃/位移、斩杀阈值与倍率、控制时长 |
| 单体或有限目标数攻击 | 强击、楼船、双射、乱射、征东、连珠、贯穿箭 | 射程、目标数、弹道/飞弹、多段或穿透 |
| 圆形/区域伤害 | 护驾、暴敛、破阵、落雷、震碎、攻城、伪书、刚愎、奇袭、枪出如龙、陷阵怒吼 | 小/中范围、目标数、持续区域、减益、自身中心/目标中心 |
| 治疗/保护/友军增益 | 安乐、守护、胡笳、青囊、遗爱、淑德、妖疗、妖疗（张宝）、御阵、忠勇、黄天、抚军、励军、筑城 | 治疗量、目标数、目标筛选、护盾、属性 Buff、溢出治疗转护甲 |
| 自身强化/持续成长 | 迅射、连射、奋威、疾击、御守、横扫、死守、不屈、老当益壮、巧工 | 攻速/暴击、护盾/护甲、触发条件、永久成长、Buff 持续时间 |
| 光环/持续团队增益 | 劝学、博物、长啸、鼓舞、安民、敦睦、直谏、镇抚、果决、长者 | 光环强度、随时间成长、自身永久成长、全队覆盖 |

> **名单核对注意**：上表只用于指导分类，不应直接视为“所有 Q1–Q2 技能”的完整统计结果。配置中有部分技能是新增批次或按剧本品质变化；还存在特别脚本、复合效果和等级字段语义。全量审计需要对每个剧本逐一筛选，并按 `HeroConfig.Skill1` 与 `SkillConfig.Sname` 关联，不能只靠技能描述或技能类别猜测。

## 4. 代表性技能拆解示例

### 4.1 征东：范围模板 + 目标数插件 + 伤害档位

该技能配置示例采用范围伤害脚本、`Area` 半径 25、最多命中 2 名目标，并逐级变化伤害数值。初步拆分：

- **模板**：目标中心圆形范围伤害（需以技能脚本核验中心语义）。
- **插件**：射程、范围档、最多目标数、每目标伤害。
- **预算重点**：受 `TargetCount` 限制，不应按照范围内无限命中估价。

[征东配置行](https://github.com/realeternia/SanTeam/blob/f18ec1aed65f27c05be68f8827369ca6a4bc35dc/Assets/Resources/Scripts/Configs/SkillConfig_s.cs#L750-L754)

### 4.2 扬鞭：单体伤害模板 + 减速插件 + 射程/频率

- **模板**：单体命中。
- **插件**：伤害档位、减速强度、减速持续时间、施法射程。
- **节奏修正**：MP 消耗与 CD 应独立记录。
- **重要语义**：当前“缓”Buff 同时降低移动速度和攻速；标价前必须按此复合效果核算，不能当作纯移速减速。

[扬鞭配置行](https://github.com/realeternia/SanTeam/blob/f18ec1aed65f27c05be68f8827369ca6a4bc35dc/Assets/Resources/Scripts/Configs/SkillConfig_s.cs#L630-L634) · [减速 Buff 实现](https://github.com/realeternia/SanTeam/blob/f18ec1aed65f27c05be68f8827369ca6a4bc35dc/Assets/Resources/Scripts/Combat/Buff/BuffSlowDown.cs#L9-L27)

### 4.3 乱射：范围模板 + 目标数 + 飞弹插件

- **模板**：在范围内选取敌人并结算群体伤害。
- **插件**：范围半径、最多目标数、每目标伤害、飞弹表现/倍率。
- **预算重点**：目标数量和飞弹伤害倍率共同决定预期总输出；不能只看单个目标的 `DamageStrength`。

[乱射配置行](https://github.com/realeternia/SanTeam/blob/f18ec1aed65f27c05be68f8827369ca6a4bc35dc/Assets/Resources/Scripts/Configs/SkillConfig_s.cs#L710-L714)

### 4.4 名门：单体主伤害模板 + 溅射插件

- **模板**：单体主目标伤害。
- **插件**：目标附近溅射范围和溅射伤害比例。
- **预算重点**：主目标与溅射目标的伤害应分别计量，溅射不是“纯单体伤害模板”。

## 6. 初步预算原则（待校准）

1. **先锁定模板，再估插件**：先决定目标选择和结算方式，再估伤害、射程、目标数、控制等插件。
2. **单体与 AoE 不直接等价**：AoE 价值取决于实际命中人数；用预期命中数校准，不要只按伤害倍率折算。
3. **射程独立计价**：射程提高会扩大可触达目标范围/改善触发机会，但不等于扩大 AoE。
4. **目标数独立计价**：目标数上限变化要与 AoE 半径共同看；“不限目标”必须显式处理。
5. **控制按覆盖量计价**：状态强度、持续时间、命中数和施放频率共同影响价值。
6. **多段和持续伤害按总量估算**：需要考虑总段数、每段间隔、持续时间和目标是否能持续留在范围中。
7. **MP/CD/概率用于频率修正**：优先用战斗数据估计每场发动次数；不要只凭单次伤害确定预算。
8. **品质先统一到基准**：Q1 是比较基线；Q2 的品质系数单独列，不与插件重复计价。
9. **价格先当预算标尺**：例如伤害档位对应的“10 元”只是内部归一化刻度，必须拿现有技能和战斗结果标定后才能作为平衡规则。
10. **特殊机制暂不强行套价**：召唤、永久成长、斩杀、驱散、位移、全图效果等先单独评审。

建议的概念性复核指标：

> 预期技能价值 ≈ 单次效果价值 × 预期命中数/结算次数 × 预期发动频率

该式仅用于发现明显失衡组合，不是游戏内伤害公式或最终价格公式。

## 7. 不改战斗逻辑的实施步骤

1. 明确本轮选择“指定剧本”还是“任一剧本 Q1–Q2 并集”。
2. 从 `HeroConfig_s.cs` 读取出场与品质字段，关联 `Skill1`；从 `SkillConfig_s.cs` 读取该 Sname 的 Lv1–5 行。
3. 对全量技能只读归类：模板、插件、施放节奏、特殊机制，并逐项确认 `ScriptName` 实际语义。
4. 输出 CSV/Markdown 清单，按风险排序：不限目标 AoE、控制覆盖、多段/持续伤害、复合 Buff、特殊脚本优先审。
5. 选取典型战斗场景记录实际命中目标数、发动次数、总伤害/治疗与控制时间，校准插件估值。
6. 先用预算表发现偏差并给出建议，不直接批量修改现有配置；待预算稳定后再决定是否逐技能调整。

## 8. 当前结论

将技能拆成“**模板项 + 插件项 + 施放节奏修正**”是可行的；将**射程提升**和**目标数**作为可组合、可独立估价的插件尤其合理。现有 `SkillConfig` 已有 `Range`、`Area`、`TargetCount`、伤害、Buff、持续时间和施放参数等配置维度，适合作为只读审计基础。

第一阶段的主要工作不是改战斗逻辑，而是：

- 按剧本品质严格导出完整 Q1–Q2 个人技能范围；
- 对每个技能确认实际脚本的选人/结算语义；
- 建立模板与插件清单及估算表；
- 用真实命中数和施放频率校准预算。

在以上步骤完成前，任何具体插件“价格”都应标注为暂定值，而不是最终平衡结论。
